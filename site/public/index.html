The gap this fills

Embedding multi-database CDC today means embedding a JVM. Debezium's engine is a Java library; Materialize and RisingWave are platforms, not crates. The Rust options are single-database primitives, and the most complete of them cannot be published to crates.io at all because it depends on a fork of a fork of rust-postgres.

rustcdc writes its own pgoutput parser against stock tokio-postgres. That is why it ships as an ordinary crate.

Four databases, one API

PostgreSQL logical replication, MySQL and MariaDB binlog, SQL Server CDC — behind one Source trait, one event envelope, one checkpoint model.

Bring your own source

register_source drives the runtime from any impl Source. The commit barrier, checkpointing, transforms and health verdicts all still apply.

No JVM, no sidecar

It is a crate. It links into your binary, uses your Tokio runtime, and has no process to supervise or control plane to operate.

Correctness you can't opt out of by accident

The failure mode that matters in CDC is not a crash — it is a wrong answer delivered as an authentic one. Where the type system can make that unrepresentable, it does.

Partial rows can't corrupt

Not every event carries a complete row. Event::row_write() returns a Merge holding only the columns the source supplied — so there is no placeholder left to write NULL with by mistake.

Checkpoints need an ack token

AckToken is #[must_use]. The durable position cannot advance past what the consumer acknowledged, because the API gives you no way to say it did.

Silent misconfiguration fails loud

MySQL's binlog_row_metadata defaults to a value under which column names vanish and updates arrive partial but complete-looking. connect() rejects it with the remedy.

Honest guarantees

At-least-once, stated plainly, with duplicates documented. No exactly-once claim appears anywhere — which is more than the reference implementation's embedded mode can say.

Transaction-atomic delivery

Opt into PreserveTransactions and no delivered batch ever ends mid-transaction — so a sink never commits a state that never existed upstream.

Idempotency that won't drop rows

The dedup guard suppresses only events it can identify. Two identical rows from a keyless table pass through rather than risk discarding a distinct one.

Measured, not asserted

Capture latency is the wall-clock time from a row committing in the source to the event reaching the consumer — measured under concurrent writes, against a single clock, so clock skew cannot flatter it. These are numbers from the gated CI harness.

PostgreSQL 16

p50 12 ms · p95 18 ms · p99 19 ms
~586 events/sec sustained on a 2,000-row workload.

MySQL 8

p50 55 ms · p95 99 ms · p99 117 ms
~375 events/sec sustained on the same workload.

Why it's trustworthy

The previous harness timed an in-memory buffer drain and could not fail. Fixing it immediately exposed a connector defect worth 15.8× on p95 — which is the argument for measuring the right thing.

Throughput is not a defensible marketing axis in this field: published third-party figures for Debezium alone span a 30× range. See the comparison for what is and is not verifiable.

Built to be verified

Deterministic replay

Replay a captured stream inside your test suite. Turns CDC from an untestable dependency into a testable one — no competitor meaningfully offers this.

Fault injection

Drop events, corrupt payloads, fail checkpoint writes, stall the source. If your pipeline does not notice, that is a finding.

Real-database CI

Integration suites run against PostgreSQL 16, MySQL 8.0/8.1, MariaDB 10.5/10.6, SQL Server 2022 and Apicurio Registry 3 containers, plus process-kill crash tests.

Docs that compile

Every Rust block on this site is compiled and run in CI. When that was switched on it failed 36 of 96 samples; all were fixed. The examples here work.
